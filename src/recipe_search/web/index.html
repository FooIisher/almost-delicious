Meal and cuisine · execution rules

Meal type is an explanation and ranking signal. Cuisine is a final requirement only when Required is selected and both dish targets below are empty. Neither filters Elasticsearch.

AND requires every group; OR accepts any alternative. Names must come from Must include or Required categories below. Empty uses any Must include ingredient.

BM25 matching boosts

Scoring only, within the content match set. Dish name phrase +12, dish type +5, cuisine boost configurable (default +6), each required ingredient +2, each positive ingredient category +2 (keywords only). Ingredient and dish-type rewards accept singular/plural forms found in the local field vocabulary; each group earns its bonus once. Category spelling is normalized (Vegetabels → vegetable). Available ingredients and meal tags receive recall bonuses; they never become required. Vector uses its editable weighted query.

Ingredient preferences and ranking

Available ingredients also boost BM25 recall; the branch tabs keep raw recall order; these reranking adjustments apply in Hybrid. Boost matching ingredients or exact tags. Avoid ingredients reduce rank, not recall. Adjust group weights in Preference settings. Healthy uses experimental per-serving thresholds (protein ≥20g, sugar ≤5g, fat ≤3g, cholesterol ≤20mg, sodium ≤140mg). Quick/fast: total time ≤30 min. Easy: exact easy tag. These are ranking bonuses only.

Retrieval settings

Each candidate count must be at least Results. RRF contribution = boost / (k + rank); boosts must be greater than zero.

Preference settings

Hybrid final score = Normalized RRF + λ × Preference Score + Rating bonus. Rating 3–5 uses rating / 5; missing or below 3 earns no bonus. Branch tabs show raw recall order. Rating bonus is independent of λ. Edit weights, then click Retrieval to apply.
