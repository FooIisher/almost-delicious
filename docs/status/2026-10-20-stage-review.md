# Prototype 1.2 阶段总结与十一月底演示准备

评估日期：2026-10-20。目标：2026 年 11 月底初步项目演示及阶段汇报。
本总结基于当前 1.2 实现、1.1 原始计划与 NEXT_VERSION_TODO、已有验证记录及本次测试。不是导师验收结果，也不将模拟测试视为模型准确率证明。

## 当前判断

已进入“功能闭环基本建立，需要冻结基线并补齐研究评估”的阶段。可以围绕 recipe search 演示完整流程，但尚不能据此声称 Hybrid、偏好重排或类别检查带来了可量化改善。距离十一月底约六周，建议将资源转向语义规则收敛、固定测试集、真实运行、对照实验和演示稳定性。

## 优先风险

1. **检索、语义检查和最终推荐之间的约束闭环。** 类别 pass 才可正式推荐已有代码约束；具体食材在 BM25 降级后可能不满足原始条件。需要用记录的实际食材核实最终推荐合规，不能仅信任“已检索到”或一句说明。
2. **数据质量决定可判断范围。** 食材、标签、总时间、份量和营养缺失/口径问题会造成错误过滤或错误解释。必须抽样审计；营养零值与缺失不可混为一谈。未知不得写成已满足。
3. **Query 与范围召回策略未被验证。** 标签范围会排除没有标签的相关食谱；长语义 Query 与简短关键词有不同效果；前端否定移除只是规则，不保证任意英语表达正确。
4. **级联丢失与延迟。** 召回 1000 → RRF 100 → 总结 20，每步都可能丢掉理想结果。类别检查可能最多五批顺序调用再总结；不能用“并行检索”推导端到端一定快。
5. **研究数据管理。** 固定 query、人工标准、索引版本、候选 ID、各阶段排序、真实延迟、用量、模型/提示词/schema/参数版本要能够关联。功能接口有这些字段不等于实验档案已经完整保存。

## 演示与论文所需证据

建议先与 Fenner 确认以下三个研究问题，再冻结比较方案：

- 意图结构与约束映射能否正确区分硬条件、软偏好、类别与具体食材？
- Hybrid + 偏好重排，相比单路或纯 RRF，是否改善相关性和偏好匹配？
- 召回后类别语义检查是否减少最终推荐的硬约束违反，代价是多少？

最小评估建议：50 条英文请求，约 20 条开发/调参、30 条冻结测试；这是建议规模，需结合标注时间与导师要求确认。对类别、否定、错拼、数值边界、无结果、冲突、范围检索均有覆盖。开发过程中已反复调试的历史案例默认属于开发集。

人工标准至少标注目标、食材角色/类型、数值比较符与单位、应执行/应澄清，以及结果相关性和条件合规性。分歧与无法判断单独记录。若只有一名标注者，应如实报告，条件允许时请第二人复核部分样本。

核心对照：BM25、Vector、纯 RRF、RRF + 偏好重排；同一索引/查询/过滤口径/候选预算/展示数量。类别检查另做有/无检查的前后对照。不要同一次同时改变 Query、权重、过滤和候选数量。

指标：意图准确率；角色/实体类型提取的 precision/recall/F1；比较符/单位正确率；结构有效率；人工分级相关性的 nDCG@10；最终推荐硬条件违反率、unknown 占比、偏好命中及空结果率；分阶段/端到端延迟；实际 tokens 与估算费用。没有全库相关性标注时，不宣称测得全库 Recall@K，可报告标注池覆盖与已知相关食谱是否进入候选。

## 建议验收门槛

**演示可用：** 正常、偏好、具体排除、类别排除、冲突、无结果、降级、失败重试各有固定路径；连续重复运行无旧结果串入；未知与过滤状态可解释；真实模型与 ES 可用，耗时可接受；失败时有诊断和录制备份。

**阶段汇报可支撑：** 至少一套冻结真实测试结果、一个有意义的 baseline 对照、一组类别判断结果、成本与延迟表、错误案例及已知限制。可讲清每个设计选择与证据。

**最终论文可支撑：** 在导师要求基础上完善可重复实验、参数/消融依据、对照公平性、标注质量说明、统计不确定性及局限讨论。初步汇报不必一次完成所有最终实验。

本阶段应优先做“冻结标准与评估”，不建议继续将主要精力投入新增意图、复杂 Agent、多轮或大幅视觉重设计。
